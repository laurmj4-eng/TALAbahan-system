# Performance Improvement Plan — TALAbahan System

## Deep System Search Results

Comprehensive analysis of all PHP controllers, Vue components, server config, and build config revealed **15 performance bottlenecks** across 5 categories.

---

## 🔴 CRITICAL — Blocks User Interaction

### 1. ActivityLogger Makes Synchronous HTTP Call on Every Request
- **File**: `app/Filters/ActivityLogger.php:73-92`
- **Problem**: Calls `file_get_contents("http://ip-api.com/json/{$ip}")` with 2s timeout on EVERY non-health, non-AJAX request
- **Impact**: Adds up to **2 seconds latency** to every page load
- **Fix**: Remove or make geolocation async (fire-and-forget via background job), or cache IP→location mapping

### 2. Eager Import of All Vue Pages
- **File**: `resources/js/main.js:38`
- **Problem**: `import.meta.glob('./Page/**/*.vue', { eager: true })` loads ALL ~20 Vue page components into a single bundle
- **Impact**: Massive initial JS payload (~5.4MB), slow first page load
- **Fix**: Change to lazy imports: `import.meta.glob('./Page/**/*.vue')` (without `eager: true`), use dynamic `import()` in resolve

### 3. Customer Dashboard Polls Every 3 Seconds
- **File**: `resources/js/Page/customer/Dashboard.vue:1070`
- **Problem**: `setInterval(fetchProducts, 3000)` polls product data every 3 seconds
- **Impact**: Constant network requests + DB queries, causes perceived sluggishness
- **Fix**: Increase to 30-60 seconds, or use WebSocket/SSE for real-time updates, or remove polling entirely (data doesn't change that fast)

### 4. Admin Dashboard Recreates Chart.js on Every Fetch
- **File**: `resources/js/Page/admin/Dashboard.vue:230-286,317`
- **Problem**: `initChart()` destroys and recreates Chart.js instance every 30 seconds
- **Impact**: Visual flicker, unnecessary DOM manipulation
- **Fix**: Update chart data in-place using `chartInstance.data.labels = ...; chartInstance.update();`

### 5. N+1 Query in Admin Orders
- **File**: `app/Controllers/Admin/Orders.php:35-38`
- **Problem**: Loops through orders and queries `order_items` count individually per order
- **Impact**: 10 queries per page load (10 orders/page × 1 query each)
- **Fix**: Use single JOIN query with COUNT aggregation (already done in `getOrders()` method at line 61-74)

## 🟠 HIGH — Significant Performance Drag

### 6. Customer Dashboard 6 Separate Count Queries
- **File**: `app/Controllers/Customer/Dashboard.php:96-131`
- **Problem**: `getCustomerOrderCounts()` makes 6 separate `countAllResults()` queries for each order status
- **Impact**: 6 DB round-trips instead of 1
- **Fix**: Single query with `GROUP BY status` or `CASE WHEN` counting

### 7. Admin Dashboard Unpaginated findAll()
- **File**: `app/Controllers/Admin/Dashboard.php:88-95`
- **Problem**: `$salesModel->orderBy('created_at', 'DESC')->findAll()` fetches ALL ledger entries
- **Impact**: Memory bloat with large datasets
- **Fix**: Add `->limit(50)` or paginate

### 8. Cache Disabled on Production
- **File**: `app/Config/Cache.php:32-34`
- **Problem**: Cache handler set to `dummy` on InfinityFree hosting
- **Impact**: No server-side caching, every request hits DB
- **Fix**: Use file-based cache with writable directory, or implement client-side caching with HTTP headers

### 9. No Compression in Server.js
- **File**: `server.js`
- **Problem**: No gzip/brotli compression middleware
- **Impact**: All responses sent uncompressed
- **Fix**: Add `compression` middleware: `app.use(compression())`

### 10. ~5.4MB JS Bundle No Code Splitting
- **File**: `vite.config.js`
- **Problem**: No manual chunk splitting configured
- **Impact**: Browser must download entire bundle before any page renders
- **Fix**: Configure manual chunks in Vite: separate vendor (Vue, Inertia, Chart.js, Leaflet) from app code

## 🟡 MEDIUM — Suboptimal

### 11. fieldExists() Called on Every getTodayProfit()
- **File**: `app/Models/OrderModel.php:152`
- **Problem**: Checks if `cost_price` column exists on every call
- **Impact**: Extra DB query per dashboard load
- **Fix**: Cache the result or remove the check if column is guaranteed to exist

### 12. Axios Interceptors Registered Per Component
- **File**: `resources/js/Page/customer/Dashboard.vue:1075-1103`
- **Problem**: CSRF interceptors registered inside `onMounted` — duplicated on every component mount
- **Impact**: Multiple interceptors stacking, potential double-header issues
- **Fix**: Register interceptors once in `main.js`

### 13. Heavy backdrop-blur CSS
- **Files**: Multiple Vue components
- **Problem**: `backdrop-blur-md` on large sections forces GPU compositing
- **Impact**: GPU memory usage, janky scroll on low-end devices
- **Fix**: Remove backdrop-blur from large sections, use solid backgrounds instead

### 14. Multiple setTimeout Calls
- **Files**: 21 setTimeout calls found across components
- **Problem**: Many small delays for UI transitions
- **Impact**: Minor but cumulative input delay
- **Fix**: Use CSS transitions/animations instead of JS timeouts

### 15. DBDebug True in Development
- **File**: `app/Config/Database.php:48`
- **Problem**: `DBDebug: true` causes full error rendering on DB errors
- **Impact**: Error pages are heavy, slow down error recovery
- **Fix**: Only enable in true debug mode, not regular development

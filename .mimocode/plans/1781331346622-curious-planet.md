# TALAbahan System - Comprehensive Improvement Plan

## Overview
Security hardening, code quality improvements, and performance optimizations for the CodeIgniter 4 + Vue 3 e-commerce system.

---

## Phase 1: Security Hardening

### 1.1 Protect Exposed Secrets in `.env`
- **File**: `.env` (line 51, 65-66, 70-76)
- **Issue**: API keys, reCAPTCHA secrets, Firebase config, DB passwords hardcoded
- **Action**: Move sensitive values to `.env` only, add `.env` to `.gitignore` verification, ensure `.env.example` has placeholders only

### 1.2 Add Authentication Guards to API Routes
- **File**: `app/Config/Routes.php` (lines 28-65)
- **Issue**: API routes under `/api` group have no auth guards — anyone can call admin/product/order endpoints
- **Action**: Add role-based API token middleware or session checks to protect:
  - `admin/*` API routes → require admin role
  - `staff/*` API routes → require staff role
  - `customer/*` API routes → require customer role
- **New file**: `app/Filters/ApiAuthFilter.php`

### 1.3 Fix SQL Injection Risks
- **File**: `app/Models/OrderModel.php` (lines 110, 155)
- **Issue**: Raw string interpolation in queries: `"created_at LIKE '{$today}%'"`
- **Action**: Use parameterized queries or CI4 Query Builder methods exclusively

### 1.4 Strengthen CORS Configuration
- **File**: `server.js` (line 17)
- **Issue**: `origin: process.env.CORS_ORIGIN || '*'` allows any origin
- **Action**: Default to specific allowed origins, require explicit CORS_ORIGIN config

### 1.5 Add Rate Limiting to API Routes
- **File**: `server.js` (line 46) and new middleware for PHP API
- **Issue**: Only chat endpoint has rate limiting; all other API routes are unprotected
- **Action**: Add rate limiting to auth endpoints (login, register) and sensitive operations

### 1.6 Fix AdminGuard Chatbot Bypass
- **File**: `app/Filters/AdminGuard.php` (lines 14-17)
- **Issue**: `strpos($path, '/admin/chatbot/')` could be bypassed with crafted paths
- **Action**: Use strict path matching or move chatbot routes outside admin group

### 1.7 Add CSRF Protection to API Routes
- **File**: `app/Config/Routes.php`
- **Issue**: API POST routes lack CSRF tokens
- **Action**: Use API tokens or session-based CSRF for state-changing API operations

## Phase 2: Code Quality & Architecture

### 2.1 Remove Duplicate Checkout Logic
- **Files**: `app/Services/CheckoutService.php` and `app/Models/OrderModel.php`
- **Issue**: Both have `placeOrder` and `createFromCheckout` doing similar work
- **Action**: Consolidate into `CheckoutService` as the single source of truth, remove `OrderModel::createFromCheckout`

### 2.2 Add Input Validation to API Controllers
- **Files**: `app/Controllers/Admin/ProductController.php`, `app/Controllers/Staff/Orders.php`, etc.
- **Issue**: Many API endpoints accept raw input without validation
- **Action**: Add validation rules in controllers or use FormRequest-style validation

### 2.3 Standardize API Response Format
- **Files**: All controllers
- **Issue**: Inconsistent response formats (some use `status`, some use `success`, some bare arrays)
- **Action**: Create `app/Controllers/ApiResponseTrait.php` with standard helpers: `success()`, `error()`, `paginated()`

### 2.4 Add Proper Error Handling
- **Files**: All controllers
- **Issue**: Try-catch blocks return raw error messages to clients
- **Action**: Use CI4 exception handler, log errors, return generic messages to clients in production

### 2.5 Extract Hardcoded Values to Config
- **Files**: `app/Services/CheckoutService.php` (line 96), `app/Models/OrderModel.php`
- **Issue**: Status strings, shipping fees, payment methods hardcoded
- **Action**: Move to `app/Config/Constants.php` or database settings

---

## Phase 3: Performance & Reliability

### 3.1 Add Caching Layer
- **Files**: `app/Models/OrderModel.php`, `app/Controllers/Admin/Dashboard.php`
- **Issue**: Dashboard stats and frequent queries hit DB every time
- **Action**: Add CI4 cache (`cache()->save()`) for dashboard stats, product listings

### 3.2 Add Database Indexes
- **File**: `mj_chatbot.sql` or new migration
- **Issue**: Missing indexes on frequently queried columns
- **Action**: Add indexes on:
  - `orders(status, created_at)` 
  - `orders(customer_name)`
  - `order_items(order_id, product_id)`
  - `users(email)` (if not exists)

### 3.3 Add Pagination to List Endpoints
- **Files**: `app/Controllers/Admin/Orders.php`, `app/Controllers/Staff/Orders.php`
- **Issue**: Some endpoints return all records without pagination
- **Action**: Add limit/offset pagination with total count

### 3.4 Add Request Throttling
- **File**: `app/Config/Filters.php` or new filter
- **Issue**: No throttling on PHP-side API routes
- **Action**: Add throttle filter for auth endpoints and sensitive operations
